# 同频提问局：阿里云 Ubuntu 22.04 部署操作手册

本文适用于 **Ubuntu 22.04 LTS**。每一步都标明操作位置、可能输出和正确结果。

## 先看懂三个操作位置

- **[本地]**：你自己的 Windows Git Bash。路径格式通常是 `/d/codex-project/同频提问局`。
- **[服务器 root]**：通过 SSH 登录阿里云后的管理员终端，提示符通常是 `root@服务器:~#`。
- **[服务器 tongpin]**：服务器上的普通运行用户，提示符通常是 `tongpin@服务器:~$`。

除非特别标明，下面的 `apt`、`nginx`、`systemctl`、`certbot` 命令都在服务器执行。

## 0. [本地] 确认要部署的代码已经进入 GitHub

```bash
cd "/d/codex-project/同频提问局"
git status --short
git rev-parse HEAD
git ls-files next-app | head
```

可能看到：

```text
 M README.md
?? next-app/
```

这表示 `next-app/` 尚未上传，服务器无法部署完整 Next.js/OAuth 应用。完整项目的正确结果是：`git status --short` 没有未处理改动；`git ls-files next-app | head` 能显示 `next-app/app/...` 等文件；GitHub 的 `origin/main` 与本地提交一致。

上传前先确认没有密钥和缓存，再执行：

```bash
printf "\n.next/\nnext-app/.next/\n" >> .gitignore
git add .gitignore README.md \
  "文档/阿里云服务器部署指南.md" \
  next-app/app next-app/lib next-app/public \
  next-app/package.json next-app/package-lock.json \
  next-app/next.config.mjs next-app/start-local.mjs next-app/README.md
git status --short
```

正确结果应列出要提交的源码，不能出现 `node_modules/`、`.next/`、`.env`、`数据/本地状态.json` 或真实密钥。确认后：

```bash
git commit -m "补充完整应用与部署指南"
git push origin main
```

常见输出：`Everything up-to-date` 表示没有新的提交；`src refspec main does not match any` 表示当前没有提交；`rejected` 时先检查远程改动，不要直接强制推送。

## 1. [服务器 root] 创建 ECS 和安全组

在阿里云 ECS 控制台创建 Ubuntu 22.04 LTS 实例并绑定公网 IP。安全组只开放 `22/TCP`、`80/TCP`、`443/TCP`，不要开放 `3000` 和 `51283`。

在本地连接：

```bash
ssh root@你的服务器IP
```

第一次出现 `The authenticity of host ... can't be established` 时输入 `yes`。成功后提示符应类似 `root@服务器:~#`。 `Permission denied (publickey)` 表示 SSH 密钥或用户名不正确。

## 2. [服务器 root] 更新系统并安装软件

```bash
apt update && apt upgrade -y
apt install -y git nginx ufw curl ca-certificates
```

正常输出会包含 `Reading package lists...`、`Setting up...`，最后回到命令提示符。

如果询问 `sshd_config` 如何处理，选择 `keep the local version currently installed`，按方向键选中后按 `Enter`。如果出现 `Which services should be restarted?`，保持默认并按 `Enter`。这两个界面都不是错误。

检查版本：

```bash
git --version
nginx -v
ufw --version
```

正确结果是分别显示版本号，具体数字可以不同。

## 3. [服务器 root] 配置防火墙

```bash
ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
ufw --force enable
ufw status verbose
```

正确结果应包含：

```text
Status: active
22/tcp ALLOW
80/tcp ALLOW
443/tcp ALLOW
```

当前 SSH 窗口仍能使用，就说明没有把自己锁在服务器外。

## 4. [服务器 root] 创建普通运行用户

```bash
adduser --disabled-password --gecos "" tongpin
usermod -aG sudo tongpin
mkdir -p /srv/tongpintw
chown -R tongpin:tongpin /srv/tongpintw
```

如果提示 `The user tongpin already exists`，说明用户已经存在，可跳过 `adduser`，继续执行 `chown`。

切换用户并确认：

```bash
su - tongpin
whoami
pwd
```

正确结果：

```text
tongpin
/home/tongpin
```

## 5. [服务器 tongpin] 克隆 GitHub 仓库

```bash
cd /srv/tongpintw
git clone https://github.com/dsad554/tongpintw.git .
git branch --show-current
git status --short
ls
```

正确结果：分支显示 `main`，`ls` 能看到 `dist`、`工具`、`文档`、`next-app` 等目录，`git status --short` 没有输出。

如果没有 `next-app`，只能部署静态网页；必须回到第 0 步补齐仓库后重新克隆。

## 6. [服务器 root/tongpin] 安装 Node.js 和依赖

先从普通用户退回 root：

```bash
exit
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs
node -v
npm -v
su - tongpin
```

正确结果：`node -v` 显示 `v22.x.x`，`npm -v` 显示版本号。

用普通用户安装和构建：

```bash
cd /srv/tongpintw/next-app
npm ci
npm run build
```

正确结果：没有 `npm ERR!`，Next.js 构建完成。构建失败时先保存错误，不要启动生产服务。

## 7. [服务器 root] 配置知乎密钥

退出到 root：

```bash
exit
mkdir -p /etc/tongpintw
nano /etc/tongpintw/zhihu.env
```

填写自己的值：

```dotenv
ZHIHU_ACCESS_SECRET=你的AccessSecret
ZHIHU_OAUTH_APP_ID=你的OAuthAppID
ZHIHU_OAUTH_APP_KEY=你的OAuthAppKey
ZHIHU_OAUTH_REDIRECT_URI=https://你的域名/api/auth/zhihu/callback
```

保存后执行：

```bash
chown root:tongpin /etc/tongpintw/zhihu.env
chmod 640 /etc/tongpintw/zhihu.env
ls -l /etc/tongpintw/zhihu.env
```

正确权限类似 `-rw-r----- root tongpin`。不要用 `cat` 把密钥打印到聊天、截图或日志中。知乎开放平台的回调地址必须与配置完全一致。

## 8. [服务器 root] 创建 systemd 服务

```bash
which node
nano /etc/systemd/system/tongpintw.service
```

写入以下内容；如果 `which node` 不是 `/usr/bin/node`，替换 `ExecStart` 路径：

```ini
[Unit]
Description=Tongpin Question Cards
After=network.target

[Service]
Type=simple
User=tongpin
WorkingDirectory=/srv/tongpintw/next-app
Environment=NODE_ENV=production
Environment=ZHIHU_ENV_FILE=/etc/tongpintw/zhihu.env
ExecStart=/usr/bin/node /srv/tongpintw/next-app/start-local.mjs start
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

启动检查：

```bash
systemctl daemon-reload
systemctl enable --now tongpintw
systemctl status tongpintw --no-pager
```

正确结果包含 `Active: active (running)`。

检查内部接口：

```bash
ss -lntp | grep -E ':3000|:51283'
curl -I http://127.0.0.1:3000/same-frequency/index.html
curl -I http://127.0.0.1:51283/api/state
```

两个 `curl` 都应返回 `200`。如果服务反复重启，用 `journalctl -u tongpintw -n 100 --no-pager` 查看原因。

## 9. [服务器 root] 配置 Nginx

```bash
nano /etc/nginx/sites-available/tongpintw
```

写入并替换域名：

```nginx
server {
    listen 80;
    server_name 你的域名 www.你的域名;
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

启用并检查：

```bash
ln -s /etc/nginx/sites-available/tongpintw /etc/nginx/sites-enabled/tongpintw
nginx -t
systemctl reload nginx
```

正确结果：`syntax is ok` 和 `test is successful`。如果提示链接已存在，说明已经启用，继续检查即可。

## 10. [阿里云 DNS、服务器和浏览器] 测试 HTTP

阿里云 DNS 添加 A 记录，记录值为服务器公网 IP。DNS 生效后在服务器执行：

```bash
curl -I http://你的域名/same-frequency/index.html
```

正确结果为 `HTTP/1.1 200 OK` 或 `HTTP/2 200`。浏览器打开 `http://你的域名/same-frequency/index.html`。 `502 Bad Gateway` 通常表示 3000 服务未运行；超时通常表示 DNS 或安全组 80 端口未配置好。

## 11. [服务器 root] 开启 HTTPS

```bash
apt install -y certbot python3-certbot-nginx
certbot --nginx -d 你的域名 -d www.你的域名
certbot renew --dry-run
```

正确结果是证书签发成功，模拟续期成功。之后用 `https://你的域名/same-frequency/index.html` 访问。OAuth 回调必须使用 `https://你的域名/api/auth/zhihu/callback`，修改环境文件后执行 `systemctl restart tongpintw`。

## 12. [浏览器] 完整验收

依次测试：首页、移动端布局、资源加载、未登录浏览、提问时 OAuth、登录后的用户信息、双浏览器匹配、消息、结束总结、卡片和个人页面。开发者工具不应出现 404、CORS 或混合内容错误。

服务器同步查看日志：

```bash
journalctl -u tongpintw -f
```

## 13. [服务器 tongpin] 更新和回滚

本地先提交并推送，服务器再更新：

```bash
su - tongpin
cd /srv/tongpintw
git pull --ff-only origin main
cd next-app
npm ci
npm run build
exit
systemctl restart tongpintw
systemctl status tongpintw --no-pager
```

构建失败时不要重启旧服务。回滚时先查看 `git log --oneline -5`，再切换到稳定提交、重新 `npm ci` 和 `npm run build`，最后重启服务。部署前备份 `/etc/tongpintw/zhihu.env` 和 `数据/`，不要把备份上传 GitHub。

## 14. 现阶段限制

只部署 `dist/` 没有 Next.js、OAuth 或跨设备数据能力。当前 `51283` 是单机文件状态服务，不是真正云数据库；多实例实时聊天、邮箱登录、消息队列、数据库备份和权限系统仍需额外开发。上线正式产品前，应为状态接口增加身份鉴权、数据隔离和访问控制。
